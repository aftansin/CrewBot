# CrewBot

Расписание и лётная книжка в одном боте: следит за подписным календарём,
присылает изменения плана, и после рейса предлагает готовый черновик
записи в книжку.

Телеграм-бот, который следит за подписным календарём рабочего плана:
присылает новые события, изменения времени, смены экипажа и отмены,
считает налёт за месяц и даёт админу сводку по пользователям.

## Быстрый старт

```bash
cp .env.example .env
nano .env            # BOT_TOKEN, ADMIN_IDS, POSTGRES_PASSWORD, DATABASE_URL
docker compose up -d --build
docker compose logs -f bot
```

Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`.
Миграции применяются автоматически при старте контейнера.

Обновление:

```bash
git pull && docker compose up -d --build
```

## Что нужно знать про логику

**Лента показывает не весь год.** Доступны текущий и следующий месяц,
причём с 1-го числа прошлый месяц из ленты пропадает. Поэтому исчезновение
события из ленты само по себе не означает отмену. Бот вычисляет окно,
которое лента реально покрывает (от минимальной до максимальной даты
в выгрузке), и считает отменой только пропажу внутри этого окна.
События в прошлом остаются в базе как архив для подсчёта налёта.

**Предохранитель.** Если лента валидна, но обрезана, бот иначе разослал бы
«отменено» по всему плану. Если за один проход из ленты пропала доля будущих
событий больше `CANCEL_GUARD_RATIO`, синхронизация отменяется целиком,
а админу уходит предупреждение. Настраивается в `.env`.

**Отменённые события не удаляются**, а получают `status = cancelled`.
Это сохраняет историю и делает синхронизацию идемпотентной: если событие
вернулось в ленту, статус переключается обратно и приходит уведомление
«вернулось в план».

**Налёт** считается по событиям с `kind = flight` за календарный месяц
в таймзоне пилота. У события есть поле `actual_block_minutes` для ручной
корректировки — если оно заполнено, в зачёт идёт оно, а не расписание.
Интерфейса для правки пока нет, поле задел на будущее.

## Структура

```
app/
  config.py              настройки, единственное место чтения окружения
  main.py                точка входа, сборка зависимостей
  scheduler.py           APScheduler, одна задача опроса на пилота
  db/
    base.py              движок и фабрика сессий
    models.py            Pilot, Event
    repo.py              все SQL-запросы
  icalendar_feed/
    fetch.py             HTTP с таймаутом и ретраями
    parse.py             ЕДИНСТВЕННЫЙ модуль, знающий формат провайдера
    types.py             ParsedEvent и хэш содержимого
  sync/
    differ.py            чистое сравнение ленты с базой, покрыто тестами
    render.py            формирование сообщений
    service.py           оркестрация
  bot/
    keyboards.py         inline-клавиатуры и callback-данные
    middlewares.py       сессия БД, объект пилота, флаг админа
    handlers/
      user.py            меню, привязка, обновление, план, налёт, настройки
      admin.py           список пользователей и карточка пилота
```

Если провайдер сменит формат выгрузки, править нужно `icalendar_feed/parse.py`
и `tests/test_parse.py`. Остальное приложение работает с `ParsedEvent`
и про эмодзи со скобками ничего не знает.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен бота |
| `ADMIN_IDS` | пусто | telegram id админов через запятую |
| `DATABASE_URL` | — | строка подключения asyncpg |
| `ICS_URL_PREFIX` | адрес провайдера | допустимый префикс ссылки подписки |
| `POLL_INTERVAL_MINUTES` | 180 | интервал по умолчанию для новых пользователей |
| `POLL_INTERVAL_MIN_MINUTES` | 15 | нижняя граница, которую может выбрать пользователь |
| `POLL_JITTER_SECONDS` | 300 | разброс старта задач |
| `CANCEL_GUARD_RATIO` | 0.5 | порог срабатывания предохранителя |
| `CANCEL_GUARD_MIN_EVENTS` | 4 | минимум событий, при котором порог имеет смысл |
| `DEFAULT_TIMEZONE` | Europe/Moscow | таймзона по умолчанию |
| `LOG_LEVEL` | INFO | уровень логирования |

## Осталось доделать

## Лётная книжка

Команда `/logbook` или кнопка в главном меню.

Записать рейс: бот показывает рейсы из расписания, которых ещё нет в
книжке. В карточке уже заполнены номер, маршрут, экипаж и плановые
времена — остаётся прислать одну строку с фактическими:

    0952 1537

Принимаются `09:52 15:37`, через дефис или слэш. Переход через полночь
разворачивается сам. Дальше выбирается борт: для разворотного рейса
предлагается тот, на котором прилетели, поиск работает по обрывку
номера (`73125`, `BCD`).

### Проверки ввода

Отклоняются: не два значения, несуществующее время, перепутанные местами
запуск и выключение, расхождение с планом больше двенадцати часов.

Показываются, но сохранить можно: рейс короче пятнадцати минут, задержка
больше четырёх часов, длительность вдвое расходится с плановой.

Отдельно ловится подмена часового пояса. Расписание приходит в московском
времени, книжка ведётся в UTC, разница ровно три часа — и набранное по
привычке московское время дало бы внешне правдоподобную запись. Если
отклонение совпадает с московским сдвигом, бот об этом скажет.

Порог длительности в двенадцать часов выведен из самой книжки: самый
длинный рейс за пятнадцать лет — 7:24, медиана 3:15.

### Связь с расписанием

После создания запись принадлежит пилоту, а не календарю. План правится
задним числом — рейс вернулся, ушёл на запасной, переставили время, —
и запись не меняется вслед за ним.

Каждая запись хранит снимок плана на момент создания. Когда лента
обновляется, расхождение обнаруживается и показывается пилоту, но
ничего не переписывается автоматически. Рейс без события в расписании
тоже полноправен: перегонка, второе плечо после запасного, замена
в последний момент.

### Ночное время

Считается автоматически: солнце ниже -6 градусов, положение вдоль
ортодромии поминутно. Определение подобрано не по справочнику, а по 1465
записям самой книжки; с 2022 года расхождение с LogTen меньше минуты.

Если координат аэропорта нет, остаётся ноль с пометкой, что расчёт не
выполнялся — выдать ноль молча означало бы утверждать, что рейс был
дневным.

### Рабочее время

Час до планового отправления и полчаса после фактического выключения.
Явка назначается по расписанию, смена заканчивается по факту.

### Рейс вручную

Кнопка «Записать вручную» в списке незаписанных рейсов. Нужна для всего,
чего нет в календаре компании: перегонка, полёт на чужом типе, работа
в другом месте. Одна строка, пять значений:

    14.09.2026 UUEE UIII 2238 0401

Дата, откуда, куда, запуск, выключение — времена в UTC, коды аэропортов
в ICAO. Порядок фиксированный: угадывать, где тут что, значит однажды
угадать неверно. Дата в будущем отклоняется, аэропорт вне справочника
принимается с предупреждением — ночное время по нему не посчитается.

Функция остаётся неподтверждённой: задания на полёт нет, выводить её
не из чего. Задаётся кнопкой в карточке рейса.

### Отчёты PDF

Меню книжки -> «Отчёты PDF». Четыре готовые формы:

* **Сводка по карьере** — итоги по годам и типам ВС на одной странице,
  для резюме;
* **За год** — месяцы таблицей плюс итог;
* **За месяц** — каждый рейс строкой;
* **Вся книжка** — все рейсы с разбивкой по годам.

Отчёты на английском и только латиницей: их принимают за рубежом, а
заодно это избавляет от встраивания шрифта с кириллицей в образ. Всё,
что приходит из данных — имена, заметки, — проходит транслитерацию и
очистку, иначе один русский символ в заметке уронил бы генерацию.

Колонок PIC и SIC в таблице рейсов нет: функция в последнем столбце
говорит то же самое, а итоги по ним есть в сводном блоке. Сводка по
карьере даёт разбивку по компаниям, годам и типам ВС одинаковыми
таблицами. Годовой и полный отчёты — альбомные.

В отчёте нет отчества и заметок: в зарубежных книжках отчества нет,
а заметки засоряли таблицу. В полном отчёте каждый год начинается
с новой страницы, и при переносе таблицы год повторяется в шапке.

Весь печатаемый текст проходит очистку: кириллица транслитерируется,
типографские кавычки и длинное тире заменяются. Один символ вне latin-1
иначе роняет генерацию целиком.

Настраиваемого конструктора нет намеренно: он превращается в десяток
вопросов перед каждым файлом, а нужных форм на деле четыре.

### Борты

Меню книжки -> «Борты». Список со статистикой: сколько рейсов и часов
на каждом, чаще используемые сверху. В карточке правятся тип, вторая
регистрация и заметка.

Добавление вручную обязательно: в ленте расписания регистрации нет,
приходит только тип. Пока борта нет в справочнике, записать на него
рейс невозможно — поиск вернёт пусто. Строка заведения:

    RA-73126/VQ-BWF 737-800 (B738)

Через слэш — вторая регистрация, если у борта их две. Тип можно не
указывать. Однопилотные типы (C172) определяются автоматически.

### Резервные копии

Кнопка «Резервная копия» в настройках или команда `/backup`. Два формата
на выбор.

**JSON** — полная копия: рейсы, экипажи, справочники, история правок.
Из неё книжку можно восстановить.

**CSV** — таблица для Excel, одна строка на рейс, экипаж в одной ячейке.
Разделитель «точка с запятой», кодировка UTF-8 с BOM: иначе Excel
открывает файл одной колонкой и портит кириллицу. Это не копия для
восстановления, а выгрузка для просмотра и переноса.

Раз в неделю JSON приходит сам: рейсы, экипажи, справочники, периоды работы и
история правок. Раз в неделю, в воскресенье утром, тот же файл приходит
сам. Расписание в копию не идёт — оно перезагружается из календаря.

Эта копия закрывает частый случай: ошиблись командой, испортили данные
правкой, потеряли том. Отказ сервера она не закрывает — там нужен дамп
всей базы. Его стоит поставить в cron на хосте:

```bash
0 5 * * 0 cd /opt/crewbot && docker compose exec -T db \
  pg_dump -U crewbot crewbot | gzip > /root/crewbot-$(date +\%F).sql.gz
```

И то и другое хранить вне сервера. Копия, лежащая рядом с оригиналом,
копией не является.

### Перенос книжки из LogTen Pro

Импорт идёт из исходной выгрузки, а не из базы flightlog: схемы
разошлись, и переливка из базы в базу была бы хрупкой. Повторный разбор
исходника надёжнее — у него встроена сверка, и он идемпотентен.

Пилот должен существовать в базе, то есть хотя бы раз написать боту
`/start`. Затем:

```bash
docker compose run --rm -v ./data:/data bot \
  python -m app.logbook_cli report /data/export.txt

docker compose run --rm -v ./data:/data bot \
  python -m app.logbook_cli import /data/export.txt --pilot-id <telegram id> --commit
```

Повторный запуск не плодит дубли: у каждого рейса есть ключ из даты,
маршрута и времени вылета. Если рейсы уже есть, импорт остановится и
потребует `--force`.
